# Build the LLM Wiki HTML view

Create or refresh `.llm-wiki/view/index.html`, a single self-contained dashboard that renders this
repo's `.llm-wiki/` **Markdown canon** for humans to review at a glance. **Do not change the Markdown
pages** — they are the source of truth that AI agents read. The HTML view is *derived* and human-only.
(If there is no `.llm-wiki/`, run the `llm-wiki-init` prompt first.)

## Steps

1. **Read the canon** (don't rewrite it):
   - `index.md` — repo name + summary, the **Stack** block, the **Map** table (area → key files →
     purpose → module), and the "Where to start by task" list.
   - each `modules/<name>.md` — title, `covers`, one-line purpose, and "Key files & entry points".
   - every page's YAML frontmatter — `updated`, `status`, `covers`.
   - the cross-links between pages, and each `## [YYYY-MM-DD] <op> | <summary>` line in `log.md`.

2. **Build a JSON data object** with these keys:
   - `repo`, `summary`, `generated` (today), `today`
   - `stack`: `[{ "label", "value" }]`
   - `map`: `[{ "area", "files": [..], "purpose", "module": "<id or null>" }]`
   - `tasks`: `[{ "label", "targets": ["<page id or raw path>", ..] }]`
   - `pages`: `[{ "id", "title", "kind": "index|page|module|log", "updated", "status", "covers": [..],
     "purpose"?, "files"? }]` — use the module's base filename as its `id` (e.g. `http-api`).
   - `links`: `[{ "from": "<id>", "to": "<id>" }]`
   - `log`: `[{ "date", "op": "init|update|lint|upgrade", "summary" }]`
   - `dataSources`: `[{ "name", "engine": "SQL Server|Oracle|PostgreSQL|SAS|Snowflake|S3|…",
     "connectVia", "auth", "notes" }]` — the external sources this repo connects to. Read the wiki's
     own `data-sources.md` **first** if it has one (that page is the authoritative repo-scoped list);
     only if it's absent, scan the connection code (pyodbc / SQLAlchemy / `DBI::dbConnect` /
     `saspy.SASsession` / `boto3` / `snowflake.connector` / `duckdb`, `Server=`/`DSN=`/`s3://`, UNC
     paths, `pg_service`, `sascfg_personal.py`). Connection shape and credential **names** only —
     **never a secret**. Omit if none.

3. **Write `.llm-wiki/view/index.html`.** If this repo already has a viewer template at
   `.llm-wiki/view/index.html`, replace only the JSON between its
   `<script id="wiki-data" type="application/json">` … `</script>` tags. Otherwise build a
   self-contained HTML page that embeds that JSON and renders: a summary row (page/module counts,
   last-updated), the Stack as badges, the Map as a filterable table, the task list as cards, an
   inline-SVG graph of the page `links`, a freshness heatmap coloring each page by how long since its
   `updated:` date (and `status`), a data-sources panel (engine · name · connect-via · auth, no secrets)
   when `dataSources` is non-empty, module cards, and the `log` as a timeline. Light + dark theme,
   responsive. Keep all state in the one JSON blob so the page can be regenerated by swapping it.

4. **Keep the view out of agent reads.** Add `.llm-wiki/view/` to `.gitignore` (it's a regenerated
   build artifact). Skip this only if the user wants to publish the view (e.g. GitHub Pages).

5. **Open it** via VS Code's **Simple Browser** (Command Palette → "Simple Browser: Show") or any
   browser. On github.com raw HTML is sanitized, so Markdown stays the rendered view there.

When done, tell me the path written and how many pages / modules / links it rendered. Re-run this
after `/llm-wiki-update` to refresh the dashboard.
