# DB

Persistence: SQLAlchemy models over Postgres, migrations via Alembic.

## Key files & entry points

- `app/db/models.py` — SQLAlchemy ORM models; source of truth for tables.
- `app/db/session.py` — engine + `SessionLocal` factory + `get_session` dependency.
- `alembic/` — migration environment (`env.py`) and `versions/` history.
- `alembic.ini` — Alembic config (DB URL usually pulled from `app.config`).

## How it works

Endpoints receive a `Session` from `get_session`. Model changes flow through Alembic autogenerate
(see [recipes](../recipes.md#add-a-migration)); review the generated migration before applying —
autogenerate misses some changes (renames, server defaults).

## Gotchas

- Keep `app/db/models.py` imported in `alembic/env.py`'s metadata, or autogenerate won't see new
  tables.
- Always review autogenerated migrations; they are a draft, not final.
- Session lifecycle is managed by the dependency — don't `commit()`/`close()` a session you didn't
  open unless the endpoint owns it.
